# 分析処理の高速化（Java 移植）

Go WebAudit PR [#41](https://github.com/mikoto2000/webaudit/pull/41)、マージコミット `e9c6cfe73c238375904e550a115ed57d1364fcef` の4候補を Java に移植しました。ルール・検出の最終判定・統計閾値は変えません。

- Aura、独自ルール、上流データ正規表現の照合前に、必須リテラルの OR で不可能な候補を除外します。最終判定は RE2/J のままです。
- ルール間でフィールド値と ASCII 小文字化結果を共有します。上流データ正規表現と Aura 署名でも、入力ごとの変換を共有します。
- 固定リストを初期化時に大文字化し、各リクエストでは入力だけを一度変換します。既存のコードポイント単位の大文字化を維持します。
- オンラインの中央値・MAD は Behavior インスタンスごとの128要素バッファを再利用します。観測値は並べ替えず、従来の到着順・保持件数・閾値を維持します。終了時の可変長ピア比較には従来の計算を使います。

## 正規表現の安全側へのフォールバック

RE2/J の非公開構文木 API に依存せず、限定した構文の読み取りで必須文字列だけを抽出します。連結では必須の子、選択ではすべての枝の必須文字列を必要とします。任意・0回反復からは必須文字列を取りません。未対応の構文（Unicode エスケープ、引用、POSIX クラス等）では式全体の事前選別を無効にします。Unicode 入力・不正な UTF-16 サロゲートも RE2/J へ直接渡します。ASCII だけの式と入力で小文字化を使うため、Unicode の大小文字同値を誤って除外しません。

既存の保存済み Go 参照レポートを更新せずに検証します。追加テストでは同梱の全データ正規表現・独自/Aura署名を RE2/J の直接照合と比較し、Unicode・任意枝・反復・生成入力を含めます。統計計算は0〜128件の各長さ、効果量の境界、観測値の不変性を旧実装と比較します。

## 再現手順

変更前と変更後を同じ JDK 25 でビルドし、次を実行します。通常のテストに Go は不要です。

```powershell
python tools/compare_analysis_performance.py /path/baseline.jar target/webauditJ.jar --lines 10000 --long-ua-lines 1000 --repeats 3 --output .workflow/analysis-performance.json
```

同じ入力ファイルを使い、変更前後の起動順を反復ごとに入れ替えます。通常1万行・長い UA（4096文字追加）1000行・攻撃20%混在1万行の3条件で、解析時間と解析スレッドの累積割当量を記録します。各回は別 JVM（64〜512 MiB ヒープ）で、クラス初期化と JIT を含み、ファイル生成・JVM 起動・JSON シリアライズは計時外です。固定時計の全レポートを Python でキー順正規化して SHA-256 比較します。通常の検出フィールドだけのハッシュではありません。実行間で入力ファイルの絶対パスが変わるため、ハッシュ比較は同じ実行内で行います。

単一 Windows 開発機での合成ログによる測定です。GeoIP・gzip・bundle 出力全体は測定対象外です。割当量は解析スレッドのみで、プロセス全体の使用量・ピークメモリではありません。長い UA 条件は既存のサンプル切り詰めにより部分解析になることがあります。Go の測定倍率を Java に流用しません。
