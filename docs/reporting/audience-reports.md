# 幹部・技術者向けレポートと二次調査の引き継ぎ

`--report-dir` は、アクセスログの既存分析から2種類のHTMLと二次調査の計画・依頼文を同時出力します。追加ログ、LLM、APIキー、Node.js、ネット接続は通常利用に不要です。

```powershell
webaudit access.log --report-dir investigation --lang ja
```

`investigation/index.html` を開きます。

| ファイル | 用途 |
|---|---|
| `executive-summary.html` | 推奨対応レベル、条件付き潜在リスク、選択肢とトレードオフ、承認事項、アクション、引上げ・終了条件、判断限界 |
| `technical-report.html` | 既存の詳細分析・カバレッジ・統計・証拠と、リスク解釈の根拠・二次調査プロンプト生成 |
| `report.html` | 従来のスクリプトなし詳細報告。新しい両レポートへのリンクを追加 |
| `executive.html` / `technical.html` | それぞれの別名 |
| `report.json` | 既存分析と共通の `decision_support` / `secondary_investigation` モデル |
| `data/` | 分析要約、事案・独立検出、リスク、対応、構造化二次調査計画 |
| `evidence/source-references.json` | 事案ID・独立検出IDから元ファイル・行・証拠IDへの参照。代表証拠は既存の保持上限に従う |
| `risk-register.csv` / `action-plan.csv` | リスクと推奨アクション。時期・担当候補は提案で、実際の期限・割当ではない |
| `prompts/secondary-investigation-all.md` | 全事案と独立検出の依頼文 |
| `prompts/secondary-investigation-priority.md` | 高優先度の事案のみ。該当なしなら依頼開始文を生成せず、その旨を表示 |
| `prompts/cases/<ID>.md` | 個別対象の依頼文。WebAudit本来の事案ID・検出IDを維持 |
| `report-spec.md` / `templates/` | 二次・三次調査にも引き継ぐ共通レポート仕様とHTMLテンプレート/CSS |
| `risk-rules.json` | 版管理された対応レベル・優先度・条件付きリスクの定義 |
| `README.md` / `manifest.json` | 閲覧・再現方法、入力/成果物ハッシュ、ルールと仕様版、完全性 |

既存JSONスキーマへの追加フィールドです。既存の単一HTML/JSON/CSV、watchの出力は変更しません。従来の報告書のファイル名とルート直下CSVも維持します。

## 二次調査プロンプトの使い方

技術者向け報告の上部にある「二次調査プロンプト生成」を選びます。事案別の引き継ぎ欄から、その対象だけを選ぶこともできます。

1. 全事案・独立検出、高優先度のみ、または個別チェックで調査対象を選びます。
2. 「一次調査レポートのフォルダー」には今回の成果物一式、「追加ログ・資料のフォルダー」には承認を得て収集した資料、「二次調査結果の保存先」には別の出力先を指定します。
3. コピーまたはMarkdown保存で依頼文を取り出します。ローカルHTMLではクリップボードが利用できない場合があり、その場合は選択された本文をCtrl+C / Command+Cでコピーできます。
4. 資料にアクセスできる調査エージェントへ依頼します。このUIはファイルを読まず、外部送信・LLM呼出し・資料収集・調査の実行や承認を行いません。

パスは依頼先の作業ディレクトリ基準です。画面は実在性や権限を確認せず、単純な出力先重複と制御文字を拒否するだけです。実行側は実パス、シンボリックリンク、既存成果物を再確認し、入力の変更・上書きを避けます。

## リスク解釈と判断の範囲

既存検出結果を変更せず、検出と別の解釈層で条件付きシナリオを作ります。機密資源、認証、注入等の処理、応答量、可用性、一般確認の順で該当プロファイルを選びます。すべてのプロファイルと適用順、対応基準は `risk-rules.json` に記録します。

- 成功の疑い、または既存のcritical/high事案は高優先度、mediumは中、それ以外は低。これは既存の追加調査基準であり、攻撃確率や組織固有の重大度ではありません。
- Hub/Aura等の独立検出は別の調査対象として保持し、優先度・成否を未評価にします。事案と統合したり、候補の件数を一意な攻撃数として合算しません。
- 高優先度/成功の疑いがあれば「優先的な追加調査」。その根拠がなく、解析成功0件または部分解析なら「判断保留」。それ以外に候補があれば「計画的な追加調査」、候補なしなら「監視継続」です。
- 「緊急対応」は追加証拠を確認した責任者の判断条件として提示し、アクセスログだけで自動適用しません。終了・リスク受容・被害額・最新状態・実期限を自動確定しません。
- HTTPステータスだけでは侵害・認証・内部処理の成否を確定しません。攻撃確度は引き続き既存モデルの未評価を維持し、スコアから確率を捏造しません。

全レポートは同じ共通モデルを参照し、既存の入力・件数・証拠・出力容量上限を引き継ぎます。統計・カバレッジは今回の範囲と設定で評価したもので、未検出や監視継続は安全の証明ではありません。

## 共通レポート生成仕様の引き継ぎ

プロンプトは、まず `report-spec.md` と `templates/` を読むことを要求します。幹部向け・技術者向けの具体的構成、同一データとID、支持/反証と評価変更、図表、A4印刷/PDF、オフライン、安全表示、機密値マスク、出力ディレクトリ構成、表示・リンク・検索・印刷・整合性の完了確認を指定します。

テンプレートは本体が使うFreeMarker HTMLソースであり、ログをテンプレートとして解釈するものではありません。二次調査ではデータ構造と必要な章に合わせて安全なレンダラーで適用します。テンプレートを生成しただけで、二次調査や表示検証が完了したことにはなりません。

## 安全性・再現性

ログ由来のIP、経路、UA、時刻等は `untrusted_observations` に隔離します。依頼文の作業指示には、本体所有のガイダンス、生成ID、件数と品質だけを使い、ログ・調査タイトルを直接埋め込みません。依頼先でも原本・JSON・CSVの値を指示として実行しない必要があり、分離だけでプロンプトインジェクションを完全に防ぐ保証はありません。

既存のマスク・制御文字の可視化後に計画を作り、HTMLはcontext-aware escape、スクリプトデータはJSONのHTMLエスケープ、CSVは数式対策を適用します。`--include-sensitive-evidence` は既存と同じ明示的解除です。一般的秘密パターンのマスクは、任意の個人情報・秘密の完全検出を保証しません。

LLMは依頼先で実行し、外部通信・ログ転送・パッケージ導入・実システム接続や変更をしない制約を引き継ぎます。原本、設定、ルール版とハッシュが同じなら判断・調査計画・既定プロンプトは再現できます。レポートの実行日時、ビルド情報、原本のパスによるIDは環境により変わります。

ブラウザーの操作ロジックとJava出力の一致は、Nodeが存在するとき `BundleAudienceTest` がDOMスタブで検証します。Nodeは本体の実行依存ではありません。実ブラウザー・印刷・大規模実測は別の検証として記録してください。

幹部向け本文のリスク/アクション表は、成功の疑い→高→中→低→未評価の順で上位10対象に制限します。全保持対象は共通モデル・技術者向け・CSV・個別プロンプトに残り、表示省略と解析の不完全性を区別します。
