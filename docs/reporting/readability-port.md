# 報告書の読みやすさと追加調査フローの移植

Go版 PR [#47](https://github.com/mikoto2000/webaudit/pull/47) と
[#48](https://github.com/mikoto2000/webaudit/pull/48)、確定コミット
`7a1095aea420eb6e7a4b7c1afd33b61377a30fba` を基準に移植しています。
Java版のバージョン・検出ルール・成否判定は引き継ぎ、リリース番号は変更しません。

- 幹部向け冒頭の3項目、リスクの種類、対応の決め方を整理。
- 技術者向けを5章と付録に再構成し、追加調査依頼・結果報告を第6章に配置。既存の章アンカーは維持。
- 各対象の観測事実・疑い・未確認事項・次の確認から、対象指定付きの調査依頼へ移動。
- 幹部向け上位10対象と調査観点の対応は事案ID、独立検出はエンジンとルールIDで照合。同じリスク名だけでは関連付けない。
- 対応を強める条件は共通条件と種類別の条件に分け、`webaudit/response-rules-2` としてJSON/CSVとHTMLで共有。
- 不審・関連アクセスCSVは分類、時刻、アクセス情報を先にし、追跡用IDを後方に配置。列名と値の対応を維持。
- 日本語・英語の合成サンプルをJavaの配布JARで再生成。ハッシュ・ローカルリンクを検証し、閲覧用の静的ディレクトリへまとめる。リポジトリのホスティング設定は本移植に含めない。

Go版からの参照値は `audience-ja-golden.json` / `audience-en-golden.json`。
独立エンジンの既存ID差と証拠の入力文脈だけを正規化し、判断支援・調査計画の内容を比較します。
参照値更新だけで互換性を判断せず、`ReportReadabilityTest`、既存の報告書テスト、
Node.jsのオフライン実行テスト、生成した成果物のハッシュ・リンク検証を併用します。

`python tools/build-report-pages.py NEW_DIRECTORY` は既存ディレクトリを上書きせず、
登録したサンプル以外を公開ディレクトリへ混ぜません。
